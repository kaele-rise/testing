# ES-CART-01 — Переход в пустую корзину из шапки

Тип: позитивный функциональный тест. Приоритет: средний.

## Предусловия

- Сайт https://vladivostok.e-sweets.ru/ доступен из браузера.
- Desktop Chromium, viewport 1280×720 (проект `chromium` в конфигурации).
- Новая сессия без cookies и localStorage; пользователь не авторизован.
- Корзина пуста. Playwright создаёт отдельный чистый BrowserContext для теста.
- Выполнены `npm ci` и `npx playwright install chromium`.

## Шаги и ожидаемые результаты

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть https://vladivostok.e-sweets.ru/ | Главная страница загружена; ссылка корзины в шапке видна. |
| 2 | Проверить количество товаров у ссылки корзины | Отображается «Корзина (0)». |
| 3 | Нажать ссылку корзины в шапке | Открывается https://vladivostok.e-sweets.ru/cart/. |
| 4 | Проверить содержимое открывшейся страницы | Видно точное сообщение «Ваша корзина пуста.». |

Постусловие: корзина остаётся пустой; данные сайта не изменены.

## Селектор

`#cart` — один переиспользуемый CSS-селектор ссылки корзины в desktop-шапке.
Объявлен в `page-objects/e-sweets-selectors.ts`. В HTML сайта проверено:
`<a href="/cart/" id="cart" ...>`.
Точное текстовое ожидание сообщения используется как проверка результата.

## Автотест и запуск

Файл: `tests/e-sweets-empty-cart.spec.ts`.

```bash
npx playwright test tests/e-sweets-empty-cart.spec.ts --project=chromium
```

Адрес сайта переопределён только для этого файла через `test.use`, потому что
общий `baseURL` репозитория указывает на planetexotic.ru.

## Результат проверки 03.11.2026

Статус сценария: **Blocked**. Запуск Chromium завершился ошибкой
`page.goto: net::ERR_TIMED_OUT` на первом шаге (лимит теста 30 секунд).
Проверки корзины не выполнялись. HTML главной страницы и `/cart/` отдельно
получен через HTTP; в нём подтверждены селектор и текст пустой корзины.
Это не успешный браузерный прогон и не доказательство работоспособности перехода.

Баг продукта не подтверждён: тайм-аут может зависеть от среды или сетевого доступа.
Для баг-репорта сначала нужно воспроизвести проблему в доступной сети и приложить
окружение, шаги, ожидаемый/фактический результат и доказательства.
